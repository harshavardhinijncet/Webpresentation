# ============================================================================
# Notes for the deployment team
# ============================================================================
#
# 1. NO AWS KEYS. The application does not read AWS_ACCESS_KEY_ID or
#    AWS_SECRET_ACCESS_KEY and does not have an S3 client. Media is either
#    served from local disk or fetched by the browser over plain HTTPS from the
#    CDN. Uploading new media is `aws s3 sync` run by a person, not something
#    the app does — so it needs no credentials of its own, and there is nothing
#    in the running service to leak.
#
#    The key that was shared earlier (AKIA2S2B…XX6SQ) should be deleted
#    in IAM. It is not in this repository or its history, but it was sent over
#    chat and must be treated as compromised.
#
# 2. https://profile.technicalhub.io IS RUNNING AN OLD COMMIT. Its /config.js
#    returns "No route", which only happens before commit e84c518. Please
#    `git pull` to the latest main rather than editing files by hand.
#
#    DO NOT hand-patch backend/src/config/env.js. The version circulated for
#    that patch is the pre-CDN file and drops two fields that other modules
#    already read:
#      - env.cookieSecure  (backend/src/utils/http.js:71) — without it the
#        session cookie never gets `Secure`, even with COOKIE_SECURE=1 set. On
#        an HTTPS site that is a silent regression, not a visible error.
#      - env.mediaBaseUrl  (routes/index.js:25, services/asset.service.js:65) —
#        without it MEDIA_BASE_URL becomes a dead setting and S3/CloudFront can
#        never be switched on.
#    The only change that patch actually needed was HOST, and HOST now defaults
#    to 0.0.0.0 on main, so no edit is required at all.
#
# 3. START COMMAND: `node backend/src/server.js` from the repository root, or
#    `cd backend && node src/server.js`. Node 20 or newer.
#    There is no build step and no `npm install` — zero runtime dependencies.
#    If a build command is required by the platform, leave it blank.
#
# 4. HEALTH CHECK: GET /api/health returns {"ok":true,"build":"..."}.
#    Please also hit it every 10 minutes from a cron or an uptime monitor. On a
#    sleeping instance the first visitor otherwise waits ~50 seconds on a blank
#    screen and assumes the site is broken.
#
# 5. DATA IS A FILE. backend/data/db.json holds all the content. If the host
#    has no persistent disk, every restart resets it to whatever is in the
#    repository — anything an admin changes through the UI is lost. Content is
#    authored by committing, so this is survivable, but it must be known.
#    If a persistent volume is available, mount it over backend/data and
#    backend/uploads.
#
# 6. SECURITY HEADERS belong at the proxy or CloudFront, not in the app:
#    Strict-Transport-Security, X-Content-Type-Options: nosniff,
#    Referrer-Policy, and a CSP. If a CSP is added it needs
#    frame-src https://www.youtube-nocookie.com or every film on the deck
#    stops playing.
#
# 7. URGENT, DO THIS FIRST. The live site was serving working credentials to
#    anonymous callers:
#      GET https://profile.technicalhub.io/api/auth/me
#      -> {"loginHint":{"adminPassword":"Admin@123", ...}}
#    Anyone with that URL could sign in as admin. The default is now off, but
#    the deployed build still has it on until you pull, and the passwords
#    themselves have been public in the repository the whole time. So:
#      a) pull the latest main and redeploy,
#      b) set ADMIN_PASSWORD and PRESENTER_PASSWORD to new values,
#      c) assume Admin@123 and Present@123 are burned, because they are.
#
# 8. There is no SESSION_SECRET. Sessions are random tokens stored in db.json
#    rather than signed cookies, so there is nothing to sign. If you have seen
#    that variable in an earlier draft of the handover notes, it was a mistake
#    and has been corrected.
